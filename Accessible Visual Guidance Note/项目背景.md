可以。把项目从“完整产品”收敛成**毕业设计规模**后，核心思路是：**只选一个香港小型区域，做“导航API定大方向 + 手机摄像头做节点确认/障碍物提醒 + 粤语语音引导”，后期再加入预置室内地图。** 人行天桥识别可以做成你的特色场景。

下面给你一个适合毕设的完整策划与开发方案。

## 一、毕设选题建议

**题目：**
**基于端侧视觉与导航API的香港视障人士小区域寻路辅助系统——以中环站至IFC商场及行人天桥为例**

**定位：**
不是做全港通用产品，而是做一个**可演示、可测试、可写论文**的原型系统。精度不追求米级，定位到“节点级”即可：用户走到某个路标、天桥入口、商场门口、电梯口，系统能识别并给出语音提示。

**推荐实验区域：**
**港铁中环站 A 出口 → 中环行人天桥 → IFC 商场室内。**
理由：
- 有室外街道、红绿灯、人行道；
- 有香港典型人行天桥、楼梯、扶梯、升降机、坡道；
- 有商场室内场景；
- Google Maps 步行导航数据相对可用；
- 地标明显，适合摄像头识别和答辩演示。

区域范围控制在 **500米 × 500米** 内，室内只做 IFC 商场一层到目标店铺的简化路线。

---

## 二、系统目标

做一个 Android 手机 App，用户说出去哪里，系统：
1. 用导航 API 规划步行大方向；
2. 用摄像头实时检测前方路标、障碍物、人行天桥入口等；
3. 判断用户是否走在正确路线上；
4. 用粤语语音引导；
5. 后期在商场内用预置地图 + 视觉地标做简易室内导航。

**精度目标：**
- 不要求连续高精度定位；
- 允许“节点确认式导航”：每隔 10–20 米有一个关键节点，识别到就确认；
- 允许用户语音确认“继续”“到了”；
- 天桥识别召回率 > 70%，障碍物提醒召回率 > 70%，即可满足毕设。

## 三、总体架构

```
手机摄像头 → YOLOv8n 端侧检测 → 结构化结果
手机GPS/IMU → 粗略位置/步数 → 节点匹配
导航API → 宏观路线 → 预期节点序列
语音输入 → 目的地 → 系统
          ↓
      规则决策状态机
          ↓
   粤语TTS语音引导
```

三个核心模块：

1. **导航模块**：Google Maps Directions API，walking 模式，给出“直行、右转、上天桥、进入商场”等宏观指令。
2. **视觉模块**：YOLOv8n 放入手机，检测障碍物、路标、天桥入口、楼梯、扶梯、玻璃门等。
3. **语音模块**：系统 TTS 粤语播报，支持简单粤语语音输入。

## 四、功能设计

### 4.1 室外导航
- 用户输入目的地，例如“IFC 苹果店”。
- 调用 Google Maps Directions API 获取步行路线。
- 把路线拆成节点序列：
  - N1：中环站 A 出口
  - N2：人行道直行
  - N3：红绿灯/斑马线
  - N4：人行天桥入口
  - N5：天桥桥面
  - N6：IFC 玻璃门
  - N7：商场扶梯/电梯
  - N8：目标店铺
- 每个节点预设：
  - GPS 大致坐标；
  - 预期视觉地标；
  - 正确语音；
  - 纠偏语音。

### 4.2 摄像头视觉感知
训练一个 **YOLOv8n** 多类检测模型，类别建议 18–22 类：

**室外/障碍物：**
行人、车辆、自行车、红绿灯、斑马线、盲道、路缘、台阶、栏杆、施工围栏、路牌、店铺招牌。

**人行天桥专项：**
天桥入口、楼梯、上行扶梯、下行扶梯、升降机、坡道、桥面、天桥栏杆、天桥出口、连接商场玻璃门。

**室内：**
玻璃门、电梯、扶梯、楼层指示牌、店铺招牌、触摸地图。

模型目标：
- 输入 640×640；
- 模型大小 < 10MB；
- 手机端延迟 < 100ms；
- mAP@0.5 达到 0.5–0.65 即可；
- 天桥入口、楼梯、扶梯、玻璃门召回率优先。

### 4.3 路线校验与决策
核心逻辑不是“摄像头直接导航”，而是：

> 导航 API 说“前方该上天桥”，摄像头看到“天桥入口/坡道”，系统才确认“走对了”。

示例规则：
- 导航指令 = 上天桥，检测到“天桥入口”且距离 < 15m → 播报“前方是天桥入口，请走右侧坡道”。
- 导航指令 = 上天桥，检测到“楼梯”但未检测到“坡道” → 播报“前方是楼梯，请寻找坡道或升降机”。
- 检测到障碍物且距离 < 3m → 立即播报“前方有障碍物，请向左绕行”。
- OCR 识别到“IFC”或“苹果店” → 确认到达节点。

### 4.4 语音引导
- 粤语为默认，英语可切换。
- 使用手机原生 TTS，离线可用。
- 播报原则：
  - 障碍物优先；
  - 路线纠正其次；
  - 节点确认再次；
  - 每次只播一个核心指令。
- 示例：
  - “直行 15 米，前方有红绿灯。”
  - “已到天桥入口，请走右边坡道。”
  - “已进入天桥，直行约 30 米。”
  - “前方玻璃门，请小心。”
  - “已进入 IFC，室内导航开始。”

### 4.5 后期室内导航
毕设不必部署蓝牙信标。简化方案：
- 预置 IFC 商场一层/两层平面图，转成节点图；
- 用 PDR（手机加速度计+陀螺仪）估算步数和方向；
- 用摄像头 OCR 识别店铺招牌、楼层指示牌；
- 识别到“苹果店”“3/F”“电梯”等，就确认当前位置；
- 用户语音确认“继续”辅助纠偏。
- 精度目标：能走到目标店铺附近即可，不要求连续定位。

## 五、数据集与模型训练

**数据采集：**
- 在中环站—IFC—天桥区域拍摄 3000–5000 张图像；
- 覆盖白天、夜晚、雨天、室内灯光；
- 天桥样本至少 1000 张，包括入口、楼梯、扶梯、升降机、坡道、桥面、出口；
- 公开数据集补充行人、车辆、红绿灯等。

**标注工具：**
LabelImg 或 Roboflow。

**训练：**
- 框架：Ultralytics YOLOv8；
- 模型：YOLOv8n；
- 训练：100 epochs，Mosaic、HSV、旋转增强；
- 导出：ONNX → TFLite INT8；
- 部署：Android TFLite Interpreter + NNAPI。

**评估指标：**
- mAP@0.5；
- 天桥入口召回率；
- 障碍物召回率；
- 手机端推理延迟；
- 任务完成率；
- 用户主观评分。

## 六、技术栈

| 模块 | 选型 |
|---|---|
| 手机端 | Android + Kotlin 或 Flutter |
| 目标检测 | YOLOv8n → TFLite |
| OCR | Google ML Kit |
| 导航 | Google Maps Directions API |
| 室内地图 | 手绘/GeoJSON 节点图 |
| 定位 | GPS + PDR + 视觉地标 |
| 语音输出 | Android TTS 粤语 |
| 语音输入 | Android SpeechRecognizer 或离线 ASR |
| 后端 | 可选 Firebase，仅存路线和反馈 |

**简化决策：**
- 不做实时大 VLM，用 YOLO + OCR + 规则；
- 不部署 BLE 信标；
- 不做全港地图；
- 只做 Android；
- 只做步行；
- 只做一个小区域。

## 八、演示脚本

答辩时可按这个流程演示：

1. 用户说：“带我去 IFC 苹果店。”
2. 系统：“已规划路线，请从 A 出口出站。”
3. 摄像头识别到红绿灯：“前方红绿灯，请等待。”
4. 识别到天桥入口：“前方 5 米是天桥入口，请走右侧坡道。”
5. 识别到楼梯：“检测到楼梯，请寻找升降机。”
6. 进入桥面：“已进入天桥，直行约 30 米。”
7. 识别到玻璃门：“前方玻璃门，请小心。”
8. 进入商场：“已进入 IFC，室内导航开始。”
9. OCR 识别到苹果店招牌：“已到达苹果店附近。”

## 九、创新点与答辩亮点

1. **导航 API + 视觉节点校验**：不是只靠 GPS，而是用摄像头确认路标，解决香港高楼遮挡导致 GPS 漂移的问题。
2. **人行天桥专项识别**：检测天桥入口、楼梯、扶梯、升降机、坡道、桥面、出口，这是香港视障出行的高频难点。
3. **低成本室内导航**：不依赖蓝牙信标，用预置地图 + OCR + PDR，适合毕设。
4. **粤语语音引导**：贴合香港本地用户。
5. **端侧轻量模型**：YOLOv8n 放入手机，隐私好、离线可用。

## 十、风险与应对

| 风险     | 应对                    |     |
| ------ | --------------------- | --- |
| GPS 漂移 | 节点确认 + 视觉地标 + 用户语音确认  |     |
| 室内信号差  | 预置地图 + PDR + OCR      |     |
| 天桥多层混淆 | 预设节点 + 指示牌 OCR + 用户确认 |     |
| 模型精度不高 | 降低类别数，优先天桥、楼梯、玻璃门、障碍物 |     |
| 手机性能不足 | YOLOv8n INT8 + 降低推理频率 |     |
