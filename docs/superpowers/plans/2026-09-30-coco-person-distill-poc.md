# 实验记录：用 COCO 的 person 冷启动我们自己的行人模型

**日期：** 2026-09-30
**起因：** 「行人类别为什么不用自带的 person，这样不是不用训练了吗？」
**结论：** **能在模型内识别，而且不需要手标一个行人框。** 但「用自带的 person」这个说法
本身要拆成两件事——下面分开说。

---

## 1. 先澄清两件事

**① 今天部署的那个模型不能认行人。** 真机日志 `模型就绪 input=416 classes=1`：
它只有一个类（垃圾桶）。

**② 但「能不能认」和类数无关。** 模型输出是 `[1, 4+nc, anchors]`，
`nc=1` 只是今天恰好为 1。多类就是这个数组长一点。
所以真正的障碍从来不是架构，而是**标注**。

**③ COCO 能覆盖我们多少类？** `scripts/probe_coco_overlap.py` 实测：
48 类里 COCO 只有 3 个对得上（`bicycle` 同名，`pedestrian`↔`person`，
`table`↔`dining table`/`chair`）。**其余 45 类 COCO 一个都没有**——
包括全部主线类（天橋入口、樓梯、台階、盲道、斑馬線、護柱、垃圾桶、交通錐）。

顺带：`table`↔`dining table` 这个映射**语义不等价**（我们是"摆在街上的桌椅"，
COCO 是室内餐桌椅），不能直接拿来用。

所以「用自带的」只省 3 类，而真正有价值的是其中两个数据量最大的类。

---

## 2. 做法：COCO 当标注老师，训进我们自己的单一模型

运行时**不跑双模型**，理由有两条硬约束：

- 真机实测 268 ms/帧（3.7 FPS）。加第二个模型约翻倍 → ~2 FPS，低于可用线；
  而我们连 NNAPI/GPU delegate 都挂不上（`litert:2.2.0` 不含 delegate 类）。
- 两个模型 = 两套类别索引契约 = 本项目已经吃过三次亏的那类静默错位。

改为：**COCO 在 HK 帧上预出框 → 训进我们自己的模型**。
新增工具 `scripts/coco_to_our_labels.py`（可复用于任何 COCO 类）与
`scripts/train_yolo.py`（通用训练入口）。

### 数据

| 项 | 值 |
|---|---|
| 帧来源 | `data/raw/myVideo` 两条香港步行视频，0.25 fps 抽帧 |
| 抽帧 | 598 张（去重后） |
| COCO 自动标注 | **488 张有目标，2,218 个行人框**（conf ≥ 0.35） |
| 切分 | **按时间顺序** train 391 / val 97（不是随机） |

**为什么必须按时间顺序切**：走路视频相邻帧几乎一样，随机切分会让验证集混进
训练集的近邻帧，指标虚高——本项目在单源数据上已经踩过这个坑。
本次 val 全部来自**第二条视频的末尾**，与 train 无近邻重叠。

### 训练

`yolo11n.pt` 微调，40 轮，imgsz 416（与部署端一致），`workers=0`，seed 42。

### 结果（ultralytics val，在未见过的片段上）

| 指标 | 值 |
|---|---|
| mAP50 | **0.794** |
| mAP50-95 | 0.537 |
| precision | **0.904** |
| recall | 0.653 |

另外做了一次「学生 vs 老师」逐框核对（两边都 conf ≥ 0.35，IoU ≥ 0.5 贪心配对）：

| 项 | 值 |
|---|---|
| 老师（COCO person）出框 | 152 |
| 学生（我们训的）出框 | 226 |
| **老师的框被学生找回** | **143 / 152 = 94%** |
| 学生框里与老师对上的 | 143 / 226 = 63% |

**读法：召回好、更"话多"。** 学生找回了 94% 的老师框，
但多出了 83 个框——蒸馏出来的学生比老师**更不精确**，这是常态。
ultralytics 的 R=0.653 是在它自己选的最佳工作点上算的（此时 P=0.90），
与我这里固定 conf=0.35 的口径不同，两者不矛盾。

---

## 3. 必须说清的局限

1. **这 0.79 / 0.90 / 0.65 衡量的是「学生学到了老师多少」，不是真实精度**
   ——验证标签就是老师自己给的。要真实精度，必须有**人工核过**的一小批
   （哪怕 30 帧），再人工统计漏检与误检。
2. 标签**继承 COCO 的错误与偏置**：遮挡、背影、伞下的人、欧美场景分布。
   它是**冷启动**，不是最终标注。
3. 这个 PoC 模型只有 1 类。正式模型里 `pedestrian` 是 48 类中的第 6 类，
   架构相同；这批 COCO 标注可以**并入**正式训练集
   （`classes.json` 里已记 `original_id: 6`，与单类模型的偏移机制一致）。

---

## 4. 顺带记下两个技术地雷（都会静默失败）

**① 单类数据集的标签类 id 必须是 0，不能写真实 id。**
我第一版把行人的真实 id `6` 写进标签，yaml 只声明了 1 类 →
ultralytics 判定"标签格式非法"并把 **488 张全部丢弃**，
报错是 `RuntimeError: No valid images found ... incorrectly formatted labels`，
**完全不提类 id**。项目里 `build_single_class_dataset.py` 本来就是
「本地索引 0 + `original_id` 记真实 id」的做法，照它做才对。

**② ultralytics 对 `train.txt` 列表里的相对路径，是按「当前工作目录」解析的，
不是按 yaml 的 `path`。**
我写的 `images/xxx.jpg` 全部找不到 → 同样报 `No valid images found`，
日志里才有一行 `[Errno 2] No such file or directory: 'images\xxx.jpg'`。
改用**标准目录布局**（`images/train`、`labels/train`）后正常，
这也是更可移植的做法。

顺带把数据集内的文件名清成安全字符（空格/逗号在下游工具链里会被切断——
本项目已两次踩到：`objective_c` 构建钩子、`cmd` 的引号解析），
改名对照写在 `rename_map.csv`。

---

## 5. 对计划的影响

- **行人不必手标。** 这是本项目**数据量最大**的类（实测 96% 的帧有人、
  中位 5 人/帧），原本是最贵的一块人工。现在可以零人工冷启动。
- **`bicycle` 同理**（COCO 同名、性能好）。
- 但**官方 workload 里根本没有「行人」这一项**——只有
  `crowds_of_people_queuing`(29)。保留 `pedestrian` 是我们为了避让安全自己加的，
  这个取舍值得在毕设里写清：是产品需要，不是文档要求。
- 产物：`data/dataset_person_poc/`（本地，已 gitignore）、
  `runs/pg_person_poc/weights/best.pt`。
