# 實驗記錄：用 COCO 的 person 冷啓動我們自己的行人模型

**日期：** 2026-09-30
**起因：** 「行人類別為什麼不用自帶的 person，這樣不是不用訓練了嗎？」
**結論：** **能在模型內識別，而且不需要手標一個行人框。** 但「用自帶的 person」這個説法
本身要拆成兩件事——下面分開説。

---

## 1. 先澄清兩件事

**① 今天部署的那個模型不能認行人。** 真機日誌 `模型就緒 input=416 classes=1`：
它只有一個類（垃圾桶）。

**② 但「能不能認」和類數無關。** 模型輸出是 `[1, 4+nc, anchors]`，
`nc=1` 只是今天恰好為 1。多類就是這個數組長一點。
所以真正的障礙從來不是架構，而是**標註**。

**③ COCO 能覆蓋我們多少類？** `scripts/probe_coco_overlap.py` 實測：
48 類裏 COCO 只有 3 個對得上（`bicycle` 同名，`pedestrian`↔`person`，
`table`↔`dining table`/`chair`）。**其餘 45 類 COCO 一個都沒有**——
包括全部主線類（天橋入口、樓梯、台階、盲道、斑馬線、護柱、垃圾桶、交通錐）。

順帶：`table`↔`dining table` 這個映射**語義不等價**（我們是"擺在街上的桌椅"，
COCO 是室內餐桌椅），不能直接拿來用。

所以「用自帶的」只省 3 類，而真正有價值的是其中兩個數據量最大的類。

---

## 2. 做法：COCO 當標註老師，訓進我們自己的單一模型

運行時**不跑雙模型**，理由有兩條硬約束：

- 真機實測 268 ms/幀（3.7 FPS）。加第二個模型約翻倍 → ~2 FPS，低於可用線；
  而我們連 NNAPI/GPU delegate 都掛不上（`litert:2.2.0` 不含 delegate 類）。
- 兩個模型 = 兩套類別索引契約 = 本項目已經吃過三次虧的那類靜默錯位。

改為：**COCO 在 HK 幀上預出框 → 訓進我們自己的模型**。
新增工具 `scripts/coco_to_our_labels.py`（可複用於任何 COCO 類）與
`scripts/train_yolo.py`（通用訓練入口）。

### 數據

| 項 | 值 |
|---|---|
| 幀來源 | `data/raw/myVideo` 兩條香港步行視頻，0.25 fps 抽幀 |
| 抽幀 | 598 張（去重後） |
| COCO 自動標註 | **488 張有目標，2,218 個行人框**（conf ≥ 0.35） |
| 切分 | **按時間順序** train 391 / val 97（不是隨機） |

**為什麼必須按時間順序切**：走路視頻相鄰幀幾乎一樣，隨機切分會讓驗證集混進
訓練集的近鄰幀，指標虛高——本項目在單源數據上已經踩過這個坑。
本次 val 全部來自**第二條視頻的末尾**，與 train 無近鄰重疊。

### 訓練

`yolo11n.pt` 微調，40 輪，imgsz 416（與部署端一致），`workers=0`，seed 42。

### 結果（ultralytics val，在未見過的片段上）

| 指標 | 值 |
|---|---|
| mAP50 | **0.794** |
| mAP50-95 | 0.537 |
| precision | **0.904** |
| recall | 0.653 |

另外做了一次「學生 vs 老師」逐框核對（兩邊都 conf ≥ 0.35，IoU ≥ 0.5 貪心配對）：

| 項 | 值 |
|---|---|
| 老師（COCO person）出框 | 152 |
| 學生（我們訓的）出框 | 226 |
| **老師的框被學生找回** | **143 / 152 = 94%** |
| 學生框裏與老師對上的 | 143 / 226 = 63% |

**讀法：召回好、更"話多"。** 學生找回了 94% 的老師框，
但多出了 83 個框——蒸餾出來的學生比老師**更不精確**，這是常態。
ultralytics 的 R=0.653 是在它自己選的最佳工作點上算的（此時 P=0.90），
與我這裏固定 conf=0.35 的口徑不同，兩者不矛盾。

---

## 3. 必須説清的侷限

1. **這 0.79 / 0.90 / 0.65 衡量的是「學生學到了老師多少」，不是真實精度**
   ——驗證標籤就是老師自己給的。要真實精度，必須有**人工核過**的一小批
   （哪怕 30 幀），再人工統計漏檢與誤檢。
2. 標籤**繼承 COCO 的錯誤與偏置**：遮擋、背影、傘下的人、歐美場景分佈。
   它是**冷啓動**，不是最終標註。
3. 這個 PoC 模型只有 1 類。正式模型裏 `pedestrian` 是 48 類中的第 6 類，
   架構相同；這批 COCO 標註可以**併入**正式訓練集
   （`classes.json` 裏已記 `original_id: 6`，與單類模型的偏移機制一致）。

---

## 4. 順帶記下兩個技術地雷（都會靜默失敗）

**① 單類數據集的標籤類 id 必須是 0，不能寫真實 id。**
我第一版把行人的真實 id `6` 寫進標籤，yaml 只聲明瞭 1 類 →
ultralytics 判定"標籤格式非法"並把 **488 張全部丟棄**，
報錯是 `RuntimeError: No valid images found ... incorrectly formatted labels`，
**完全不提類 id**。項目裏 `build_single_class_dataset.py` 本來就是
「本地索引 0 + `original_id` 記真實 id」的做法，照它做才對。

**② ultralytics 對 `train.txt` 列表裏的相對路徑，是按「當前工作目錄」解析的，
不是按 yaml 的 `path`。**
我寫的 `images/xxx.jpg` 全部找不到 → 同樣報 `No valid images found`，
日誌裏才有一行 `[Errno 2] No such file or directory: 'images\xxx.jpg'`。
改用**標準目錄佈局**（`images/train`、`labels/train`）後正常，
這也是更可移植的做法。

順帶把數據集內的文件名清成安全字符（空格/逗號在下游工具鏈裏會被切斷——
本項目已兩次踩到：`objective_c` 構建鈎子、`cmd` 的引號解析），
改名對照寫在 `rename_map.csv`。

## 5. 對計劃的影響

- **行人不必手標。** 這是本項目**數據量最大**的類（實測 96% 的幀有人、
  中位 5 人/幀），原本是最貴的一塊人工。現在可以零人工冷啓動。
- **`bicycle` 同理**（COCO 同名、性能好）。
- 但**官方 workload 里根本沒有「行人」這一項**——只有
  `crowds_of_people_queuing`(29)。保留 `pedestrian` 是我們為了避讓安全自己加的，
  這個取捨值得在畢設裏寫清：是產品需要，不是文檔要求。
- 產物：`data/dataset_person_poc/`（本地，已 gitignore）、
  `runs/pg_person_poc/weights/best.pt`。
