# Roboflow people-detection 數據集：規模夠了，但**來源合法性不可驗證**

**日期：** 2026-10-02
**目標：** 下載 Roboflow 數據集，補 `bicycle`（13 幀/15 框）與 `pedestrian` 的數據。
**結論：** 數據下到了、框數很可觀，但**來源與許可證無法驗證，不建議直接用於畢設訓練**。
另發現並修掉一個會讓 7261 張圖全變成錯誤負樣本的靜默 bug。

---

## 1. 規模：確實可觀

`chris-law/people-detection-o4rdr-nlryq` v1，**7261 張**（train 5070 / valid 1431 / test 760）。

導入 dry-run 實測（映射到本項目類別後）：

| 類別 | 該數據集提供 | 本項目現有 | 倍數 |
|---|---:|---:|---|
| pedestrian (6) | **29,857 框** | 2,218 框 | **13.5×** |
| bicycle (11) | **2,038 框** | 15 框 | **136×** |
| （未映射被跳過） | 13,002 框 | — | — |

`bicycle` 正是本項目的數據死角，所以這個數字很有吸引力。

## 2. 但它是 14 個上游項目的拼盤，來源無法驗證

隨數據集附帶的 `README.dataset.txt` 自己寫明：從 Universe 上多個項目"curated"而來。
列出 14 個上游，其中 **13 個標記 CC BY 4.0**（要求署名，可接受），
但 **`MOT17-03-DPM` 沒有列許可證**——MOT17 是行人跟蹤基準，
通常**僅限研究、需註冊同意**。而 `data.yaml` 裏聚合版本自身寫的是 **`license: Private`**。

### 嘗試定位並排除那個來源——失敗了

想法：MOT17 的幀名是 6 位數字（`000001.jpg`），也許能按文件名精確排除。

做法得到的結果**推翻了假設**：數字命名的 474 張裏，除 pedestrian/bicycle 外還有
`Stopper` 852、`Signboard` 284、`helmet` 505、`Car` 284、`Cyclist` 73——
**MOT17 官方標註只有 pedestrian**，不會出現 Stopper/Signboard/helmet。
再查分辨率：該組 284 張是 1920×1080（像 MOT17-03），但同組另外 190 張是 500×376 等。
**即「數字命名」並非單一來源。**

結論：Roboflow 導出會抹掉來源身份（只剩 `原名_jpg.rf.<哈希>.jpg`），
**無法從導出物重建「哪張圖來自哪個上游」**。因此**無法證明已排除無許可證的部分**——
對要寫進論文並可能公開的畢設來説，這比數據不夠更麻煩。

> 因此 `import_roboflow.py` 的 `--exclude-name-regex` 保留為通用機制，
> 但幫助文本已明確：**文件名只是猜測，不能作為"已排除某來源"的依據**。
> 我原本在幫助文本里寫了「可用它精確排除 MOT17」，那是錯的，已刪除。

## 3. 域與標籤質量（可計算的指標）

用 `scripts/analyze_roboflow_domain.py` 抽 1500 張測：

| 指標 | 實測 | 判斷 |
|---|---|---|
| 灰度圖佔比 | 1.7% | 不是 CCTV/熱成像數據，好 |
| 框長寬比中位（寬/高） | 0.281（≈1:3.6） | **全身標註**，不是隻有頭，好 |
| 框高佔圖比中位 | 0.183 | 街邊行人視角的合理量級 |
| 框中心縱向中位 | 0.453 | 輕微偏上，不是俯視機位 |
| 每圖框數 | 中位 3，最大 96 | 多數正常，少數人潮圖 |

**域本身不算離譜**（彩色、全身、街邊視角），比 CCTV/航拍數據集接近得多。

### 但標註風格不一致

「人」的框來自至少 6 種寫法：`Pedestrian` 3371 / `person` 3144 / `people` 96 /
`Persona` 60 / `persons` 34 / `Pedestrians` 19 / `Pessoa` 17。
不同上游的"人"標註口徑（部分遮擋怎麼標、畫到什麼邊界）並不一致。
這不必然是問題，但**不能假定統一**，要按上游分別抽查。

## 4. 順帶修掉的靜默 bug（這個與取捨無關，必須修）

導入時 `data.yaml` 讀出的類別名是**空列表**。原因：`read_yaml_names` 假定
`names:` 下的列表項一定縮進，而 Roboflow 導出是**頂格**寫法（`- '0'` 在第 0 列），
第一個列表項就 `break`。

後果不是報錯，是安靜地錯到底：

```
類別名空 -> 映射空 -> 每個框都判為「未映射」而跳過
        -> 但仍寫出標籤文件（空文件）
        -> 7261 張圖配 7261 個空標籤
```

空標籤在 YOLO 裏是**有效負樣本**（"這張圖裏什麼都沒有"）。
等於往訓練集灌 7261 張錯誤負樣本，**不報錯、不崩潰**，只是模型對所有類視而不見。

修法：支持頂格塊序列 / 縮進塊序列 / 縮進映射 / 單行四種寫法，
只在「既不是列表項、也不是縮進映射」時判定塊結束。
`tests/test_roboflow_yaml.py` 第一條測試直接用與真實文件**逐字符同構**的頂格樣例。

## 5. 另外兩處防腐設計

- `--class-override-file`：映射從文件讀。忘了傳 override 時
  `import_roboflow.py` 只做精確名匹配，`person`/`Persona`/`Pessoa`/`people`/`persons`/`bike`
  這些**數據大頭會被跳過**（會打印警告，但不看輸出就會以為導入成功）。
  `fetch_roboflow.py` 下載後把建議映射寫到數據集旁的 `_class_override.json` 並帶上它。
- 「故意不映射」守衞測試：`Cyclist` 是**騎車的人**（人+車），不是本項目的
  `bicycle`（單車，一個障礙物）。映過去會讓視障用户聽到"單車"而實際是一個騎過來的人。
  同理 `player`/`head`/`Signboard`/`Stopper`/`diningtable`/數字類/車輛類全部保持不映射。
