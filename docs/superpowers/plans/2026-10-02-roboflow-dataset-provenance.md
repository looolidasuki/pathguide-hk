# Roboflow people-detection 数据集：规模够了，但**来源合法性不可验证**

**日期：** 2026-10-02
**目标：** 下载 Roboflow 数据集，补 `bicycle`（13 帧/15 框）与 `pedestrian` 的数据。
**结论：** 数据下到了、框数很可观，但**来源与许可证无法验证，不建议直接用于毕设训练**。
另发现并修掉一个会让 7261 张图全变成错误负样本的静默 bug。

---

## 1. 规模：确实可观

`chris-law/people-detection-o4rdr-nlryq` v1，**7261 张**（train 5070 / valid 1431 / test 760）。

导入 dry-run 实测（映射到本项目类别后）：

| 类别 | 该数据集提供 | 本项目现有 | 倍数 |
|---|---:|---:|---|
| pedestrian (6) | **29,857 框** | 2,218 框 | **13.5×** |
| bicycle (11) | **2,038 框** | 15 框 | **136×** |
| （未映射被跳过） | 13,002 框 | — | — |

`bicycle` 正是本项目的数据死角，所以这个数字很有吸引力。

## 2. 但它是 14 个上游项目的拼盘，来源无法验证

随数据集附带的 `README.dataset.txt` 自己写明：从 Universe 上多个项目"curated"而来。
列出 14 个上游，其中 **13 个标记 CC BY 4.0**（要求署名，可接受），
但 **`MOT17-03-DPM` 没有列许可证**——MOT17 是行人跟踪基准，
通常**仅限研究、需注册同意**。而 `data.yaml` 里聚合版本自身写的是 **`license: Private`**。

### 尝试定位并排除那个来源——失败了

想法：MOT17 的帧名是 6 位数字（`000001.jpg`），也许能按文件名精确排除。

做法得到的结果**推翻了假设**：数字命名的 474 张里，除 pedestrian/bicycle 外还有
`Stopper` 852、`Signboard` 284、`helmet` 505、`Car` 284、`Cyclist` 73——
**MOT17 官方标注只有 pedestrian**，不会出现 Stopper/Signboard/helmet。
再查分辨率：该组 284 张是 1920×1080（像 MOT17-03），但同组另外 190 张是 500×376 等。
**即「数字命名」并非单一来源。**

结论：Roboflow 导出会抹掉来源身份（只剩 `原名_jpg.rf.<哈希>.jpg`），
**无法从导出物重建「哪张图来自哪个上游」**。因此**无法证明已排除无许可证的部分**——
对要写进论文并可能公开的毕设来说，这比数据不够更麻烦。

> 因此 `import_roboflow.py` 的 `--exclude-name-regex` 保留为通用机制，
> 但帮助文本已明确：**文件名只是猜测，不能作为"已排除某来源"的依据**。
> 我原本在帮助文本里写了「可用它精确排除 MOT17」，那是错的，已删除。

## 3. 域与标签质量（可计算的指标）

用 `scripts/analyze_roboflow_domain.py` 抽 1500 张测：

| 指标 | 实测 | 判断 |
|---|---|---|
| 灰度图占比 | 1.7% | 不是 CCTV/热成像数据，好 |
| 框长宽比中位（宽/高） | 0.281（≈1:3.6） | **全身标注**，不是只有头，好 |
| 框高占图比中位 | 0.183 | 街边行人视角的合理量级 |
| 框中心纵向中位 | 0.453 | 轻微偏上，不是俯视机位 |
| 每图框数 | 中位 3，最大 96 | 多数正常，少数人潮图 |

**域本身不算离谱**（彩色、全身、街边视角），比 CCTV/航拍数据集接近得多。

### 但标注风格不一致

「人」的框来自至少 6 种写法：`Pedestrian` 3371 / `person` 3144 / `people` 96 /
`Persona` 60 / `persons` 34 / `Pedestrians` 19 / `Pessoa` 17。
不同上游的"人"标注口径（部分遮挡怎么标、画到什么边界）并不一致。
这不必然是问题，但**不能假定统一**，要按上游分别抽查。

## 4. 顺带修掉的静默 bug（这个与取舍无关，必须修）

导入时 `data.yaml` 读出的类别名是**空列表**。原因：`read_yaml_names` 假定
`names:` 下的列表项一定缩进，而 Roboflow 导出是**顶格**写法（`- '0'` 在第 0 列），
第一个列表项就 `break`。

后果不是报错，是安静地错到底：

```
类别名空 -> 映射空 -> 每个框都判为「未映射」而跳过
        -> 但仍写出标签文件（空文件）
        -> 7261 张图配 7261 个空标签
```

空标签在 YOLO 里是**有效负样本**（"这张图里什么都没有"）。
等于往训练集灌 7261 张错误负样本，**不报错、不崩溃**，只是模型对所有类视而不见。

修法：支持顶格块序列 / 缩进块序列 / 缩进映射 / 单行四种写法，
只在「既不是列表项、也不是缩进映射」时判定块结束。
`tests/test_roboflow_yaml.py` 第一条测试直接用与真实文件**逐字符同构**的顶格样例。

## 5. 另外两处防腐设计

- `--class-override-file`：映射从文件读。忘了传 override 时
  `import_roboflow.py` 只做精确名匹配，`person`/`Persona`/`Pessoa`/`people`/`persons`/`bike`
  这些**数据大头会被跳过**（会打印警告，但不看输出就会以为导入成功）。
  `fetch_roboflow.py` 下载后把建议映射写到数据集旁的 `_class_override.json` 并带上它。
- 「故意不映射」守卫测试：`Cyclist` 是**骑车的人**（人+车），不是本项目的
  `bicycle`（单車，一个障碍物）。映过去会让视障用户听到"單車"而实际是一个骑过来的人。
  同理 `player`/`head`/`Signboard`/`Stopper`/`diningtable`/数字类/车辆类全部保持不映射。
