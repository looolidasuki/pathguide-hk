# 里程碑：3 类模型（人 / 单车 / 垃圾桶）与类别映射表重构

**日期：** 2026-09-30
**目标：** 把 COCO 冷启动的 `pedestrian`、`bicycle` 并进正式训练集，
出一版**同时会认垃圾桶和人**的模型，在真机上试。
**结论：** 模型做出来了，离线指标合格，App 侧的类别映射机制已从「单类偏移」
改成**显式映射表**；只差真机验证（手机当时没连上）。

---

## 1. 为什么必须重构映射机制

先前的机制是「**加一个常数偏移**」：单类模型输出本地索引 0，
原生加 7 就变成垃圾桶的真实 id。3 类以上这个办法失效——
除非真实 id 恰好连续，否则一个常数表达不了。

改成**显式映射表**：下标 = 模型本地索引，值 = 项目类别表真实 id。

```dart
// app/lib/vision/model_class_map.dart
const List<int> modelClassIds = <int>[6, 11, 7]; // pedestrian, bicycle, bin
```

空表表示「不需要映射」（模型类别数已等于项目类别表）。单类是长度 1 的特例。

**这是本项目最贵的一类错误（类别索引错位）的唯一防线**：声明错了不会崩、
不会报错，只会让每个框的名字是另一个类。所以三处同时守：

| 位置 | 作用 |
|---|---|
| `model_class_map_test.dart` | 9 条断言：逐项映射、越界返回 null、长度不符/重复/越界 id 一律返回 null（**宁可失败也不猜**） |
| `export_tflite.py` | 导出时交叉核对模型类别数与 `modelClassIds` 长度一致，并打印出「本地索引 0..2 分别对应 pedestrian/bicycle/bin」 |
| `VisionPlugin.kt` | 原生侧长度不符时**拒绝加载**并说明原因，而不是猜一个映射 |

## 2. 数据集：532 张 / 3 类

| 来源 | 图 | 框 | 标注方式 |
|---|---|---|---|
| `pedestrian` | 488 | 2,218 | COCO `person` 自动标注（conf ≥ 0.35） |
| `bicycle` | 13 | **15** | COCO `bicycle` 自动标注 |
| `bin` | 44 | 88 | **人工复核过** |
| 合计 | **532** | 2,321 | train 427 / val 105 |

新增 `scripts/build_multiclass_dataset.py`。

### 2.1 合并时必须**按帧**合并标签，不能拼接

`pedestrian` 与 `bicycle` 的自动标注来自**同一批帧**。直接拼接会让同一张图
出现两次：一次只有人的框、一次只有自行车的框。训练时模型看到「这张图没有人」，
于是**学会抑制**本该出现的类——指标看着还行，实际两类互相打架。

实测：13 张自行车帧**全部**也含人，合并后每张图同时带 `0`（人）与 `1`（自行车）标签。

### 2.2 三个静默失败的坑（都实际踩到了）

**① 文件名截断导致静默覆盖。**
抽帧文件名是 `<视频名>_<帧号>.jpg`，**唯一的帧号在末尾**。
早先写 `safe_stem(name)[:92]`：视频名本身就超 92 字符，几百张图被截成同一个名字、
互相覆盖，最终只写出 47 个文件，而脚本还打印「合并 545 张」。
现在命名保留末尾 + 哈希兜底，并**在碰撞时报错**（覆盖比报错危险得多）。

**② 合并键用错了。**
按「源文件**路径**」做键时，两个派生数据集各自复制了一份帧、路径不同，
同一张图被当成两张——正好落进上面 2.1 那个有害情况。
**帧名才是帧的身份**，已改。

**③ 全局时间顺序切分让 val 里只剩一个类。**
44 张垃圾桶照片的文件名以 `b` 开头、排在 `myVideo_...` 之前，全落进 train；
13 张自行车帧在视频前段，也全落进 train。于是 val 的 275 个实例**全是行人**，
bin/bicycle 指标根本算不出来，而汇总数字照样好看。
改为**按「涉及哪些类」分组、组内再按时间顺序**：每类都进 val，
组内仍无近邻泄漏。

## 3. 逐类指标（平衡切分后，模型 `runs/pg_poc3/weights/best.pt`）

| 本地 idx | 类 | val 实例 | P | R | mAP50 | mAP50-95 |
|---|---|---|---|---|---|---|
| 0 | pedestrian | 242 | 0.746 | 0.718 | **0.790** | 0.536 |
| 1 | bicycle | **2** | 0.844 | 0.500 | 0.496 | 0.446 |
| 2 | **bin** | 19 | 0.698 | **1.000** | **0.948** | 0.720 |
| | 合计 | 263 | 0.763 | 0.739 | 0.744 | 0.567 |

**读法：**

- `bin` 用的是**人工复核过**的标签，表现最好（mAP50 0.948、召回 100%）——
  与「标签质量决定上限」这条一致。
- `pedestrian` 的标签来自 COCO，0.790 衡量的是「学到了老师多少」，不是真实精度。
- **`bicycle` 的指标没有意义**：val 只有 2 个实例。根本原因是尖沙咀步行区
  几乎没有单车——598 帧里只扫到 13 帧 / 15 个框。这一类需要另找素材
  （例如新界单车径），不能靠这两条片子。
