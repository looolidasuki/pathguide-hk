# 里程碑：3 類模型（人 / 單車 / 垃圾桶）與類別映射表重構

**日期：** 2026-09-30
**目標：** 把 COCO 冷啓動的 `pedestrian`、`bicycle` 並進正式訓練集，
出一版**同時會認垃圾桶和人**的模型，在真機上試。
**結論：** 模型做出來了，離線指標合格，App 側的類別映射機制已從「單類偏移」
改成**顯式映射表**；只差真機驗證（手機當時沒連上）。

---

## 1. 為什麼必須重構映射機制

先前的機制是「**加一個常數偏移**」：單類模型輸出本地索引 0，
原生加 7 就變成垃圾桶的真實 id。3 類以上這個辦法失效——
除非真實 id 恰好連續，否則一個常數表達不了。

改成**顯式映射表**：下標 = 模型本地索引，值 = 項目類別表真實 id。

```dart
// app/lib/vision/model_class_map.dart
const List<int> modelClassIds = <int>[6, 11, 7]; // pedestrian, bicycle, bin
```

空表表示「不需要映射」（模型類別數已等於項目類別表）。單類是長度 1 的特例。

**這是本項目最貴的一類錯誤（類別索引錯位）的唯一防線**：聲明錯了不會崩、
不會報錯，只會讓每個框的名字是另一個類。所以三處同時守：

| 位置 | 作用 |
|---|---|
| `model_class_map_test.dart` | 9 條斷言：逐項映射、越界返回 null、長度不符/重複/越界 id 一律返回 null（**寧可失敗也不猜**） |
| `export_tflite.py` | 導出時交叉核對模型類別數與 `modelClassIds` 長度一致，並打印出「本地索引 0..2 分別對應 pedestrian/bicycle/bin」 |
| `VisionPlugin.kt` | 原生側長度不符時**拒絕加載**並説明原因，而不是猜一個映射 |

## 2. 數據集：532 張 / 3 類

| 來源 | 圖 | 框 | 標註方式 |
|---|---|---|---|
| `pedestrian` | 488 | 2,218 | COCO `person` 自動標註（conf ≥ 0.35） |
| `bicycle` | 13 | **15** | COCO `bicycle` 自動標註 |
| `bin` | 44 | 88 | **人工複核過** |
| 合計 | **532** | 2,321 | train 427 / val 105 |

新增 `scripts/build_multiclass_dataset.py`。

### 2.1 合併時必須**按幀**合併標籤，不能拼接

`pedestrian` 與 `bicycle` 的自動標註來自**同一批幀**。直接拼接會讓同一張圖
出現兩次：一次只有人的框、一次只有自行車的框。訓練時模型看到「這張圖沒有人」，
於是**學會抑制**本該出現的類——指標看着還行，實際兩類互相打架。

實測：13 張自行車幀**全部**也含人，合併後每張圖同時帶 `0`（人）與 `1`（自行車）標籤。

### 2.2 三個靜默失敗的坑（都實際踩到了）

**① 文件名截斷導致靜默覆蓋。**
抽幀文件名是 `<視頻名>_<幀號>.jpg`，**唯一的幀號在末尾**。
早先寫 `safe_stem(name)[:92]`：視頻名本身就超 92 字符，幾百張圖被截成同一個名字、
互相覆蓋，最終只寫出 47 個文件，而腳本還打印「合併 545 張」。
現在命名保留末尾 + 哈希兜底，並**在碰撞時報錯**（覆蓋比報錯危險得多）。

**② 合併鍵用錯了。**
按「源文件**路徑**」做鍵時，兩個派生數據集各自複製了一份幀、路徑不同，
同一張圖被當成兩張——正好落進上面 2.1 那個有害情況。
**幀名才是幀的身份**，已改。

**③ 全局時間順序切分讓 val 裏只剩一個類。**
44 張垃圾桶照片的文件名以 `b` 開頭、排在 `myVideo_...` 之前，全落進 train；
13 張自行車幀在視頻前段，也全落進 train。於是 val 的 275 個實例**全是行人**，
bin/bicycle 指標根本算不出來，而彙總數字照樣好看。
改為**按「涉及哪些類」分組、組內再按時間順序**：每類都進 val，
組內仍無近鄰泄漏。

## 3. 逐類指標（平衡切分後，模型 `runs/pg_poc3/weights/best.pt`）

| 本地 idx | 類 | val 實例 | P | R | mAP50 | mAP50-95 |
|---|---|---|---|---|---|---|
| 0 | pedestrian | 242 | 0.746 | 0.718 | **0.790** | 0.536 |
| 1 | bicycle | **2** | 0.844 | 0.500 | 0.496 | 0.446 |
| 2 | **bin** | 19 | 0.698 | **1.000** | **0.948** | 0.720 |
| | 合計 | 263 | 0.763 | 0.739 | 0.744 | 0.567 |

**讀法：**

- `bin` 用的是**人工複核過**的標籤，表現最好（mAP50 0.948、召回 100%）——
  與「標籤質量決定上限」這條一致。
- `pedestrian` 的標籤來自 COCO，0.790 衡量的是「學到了老師多少」，不是真實精度。
- **`bicycle` 的指標沒有意義**：val 只有 2 個實例。根本原因是尖沙咀步行區
  幾乎沒有單車——598 幀裏只掃到 13 幀 / 15 個框。這一類需要另找素材
  （例如新界單車徑），不能靠這兩條片子。
